# 剪映草稿剪辑

默认中文。MCP 获取项目、素材信息和画面证据，模型作剪辑决策，Python 把结构化计划写成新的剪映草稿。生成草稿不是渲染成片，也不是已经在剪映中验收。

## 先确认实际条件

- 区分咨询、制定剪辑计划和实际生成草稿；咨询不写草稿。保留用户指定的故事、镜头意图和声音约束。
- 发现当次可用 MCP，不按工具前缀猜能力。工作台工具通常属于 `video_workspace_assets`；`video_editor` 可能是另一款编辑器，不能混用其项目 ID。
- 使用 `projects_list`、`assets_list` 查询授权范围；有现成工程时使用 `assembly_capabilities`、`assembly_list`、`assembly_get`，保存工程 ID、versionId 和 revision。
- 从工具列表确认存在 `assets_resolve_path` 后，先 `assets_list` 取得素材 ID 与最新 `updatedAt`，再逐个调用 `assets_resolve_path({assetId, expectedUpdatedAt})` 获取图片/视频/音频的受管绝对路径。将返回的 `assetId/kind/path` 显式映射到计划的 `id/kind/path`；保留返回的 `projectId/updatedAt/size` 作为来源检查信息，不把它们塞入不支持的计划字段。
- 路径仅在工作台同一电脑有效；只可读取本任务所选文件，不表示获准扫描相邻目录或改写原片。调用前确认本地剪辑在用户授权内；执行 Python 前重新查询所选素材路径和修订，更新或撤权时停止，不使用旧路径缓存绕过。路径已交付后 MCP 无法撤回外部程序的文件系统访问能力，不声称关闭 MCP 会终止已启动的外部读取。
- 旧实例没有此工具时，说明需要升级并重连刷新工具列表，或使用用户提供的精确路径；不扫描 userData、SQLite 或工作台受管存储来补路径，不复用令牌绕过 MCP。MCP 不提供任意磁盘文件读取或远端下载。
- 同时需要用户指定剪映草稿根目录，可在剪映设置中查看；不猜安装目录或默认草稿目录。执行命令时明确列出允许读取的素材根目录。
- 一般工作流只读 MCP 即可，不为生成外部剪映草稿要求开启工作台写权限。修改工作台工程是另一项写操作，必须在本次授权内。

## 素材判断与剪辑计划

使用 `assembly_inspect_media` 先取得实际时长与尺寸，再选择取帧时间。根据候选切点加密检查；取帧不等于观看完整动态表演，音轨信息也不等于已经听审。具备授权本地文件和相应工具时，可进一步解码、播放和听审。没有证据时标记待验证，不凭文件名决定表演优劣。

如任务涉及表演、节奏、长镜头、动作匹配或连续性，且环境提供 `cinematic-stream-editor`，读取并使用该技能的本地适配和相应参考；它负责剪辑判断，本技能负责剪映输出。不要求安装 Resolve 或更换用户的软件。

先形成可检查的计划：素材 ID 与本地路径映射、源入出点、成片位置、声音处理、字幕和切点理由。不得为了凑时长擅自重复、定格、倒放、变速，或删除指定声音。计划可能在用户已经授权的完整剪辑任务中直接执行，不强制为每个片段反复确认；遇到缺素材、重大创意变化、覆盖或新付费行为才停下询问。

## 生成草稿

执行前读取 [references/plan-format.md](references/plan-format.md)，按受支持格式创建计划 JSON。脚本不直接转换工作台完整工程；必须显式映射，保留原工程，并列出不兼容项。

用户只要求把素材导入草稿、稍后再剪辑时，使用 `mode: "importOnly"`，三个时间线数组留空；只建立素材区，不自行裁切、铺轨或截短音频。素材列表只放本次选定文件，支持 `name` 保留工作台可读名称。

1. 检查所选 Python 与依赖。脚本要求 Python 3.8+，建议专用 Python 3.11 环境；不能直接假定系统 `python` 兼容。脚本以 `pyJianYingDraft==0.3.1` 为适配基线；运行时核对版本。缺少或版本不同则报告，不自动安装、升级或修改全局环境。确需安装时先获得授权，使用专用 venv；不能把“创建技能”当作已授权安装第三方代码。
2. 默认运行预检查，不导入第三方库、不创建输出目录：

   ```powershell
   python "<技能目录>/scripts/jianying_draft.py" "<计划.json>" --media-root "<用户授权素材目录>"
   ```

3. 获得本次生成授权、确认素材及输出目录后，增加 `--execute` 和 `--draft-root`：

   ```powershell
   python "<技能目录>/scripts/jianying_draft.py" "<计划.json>" --media-root "<用户授权素材目录>" --draft-root "<剪映草稿根目录>" --execute
   ```

   多个素材根目录重复传 `--media-root`。对 MCP 返回文件可使用其父目录做脚本的范围校验，但只把已解析的素材加入计划；该参数不扩大 MCP 授权，不用于枚举同目录其他文件。需要固定 Python 时改用已选环境的解释器绝对路径，而非改变系统默认 Python。

4. 脚本只创建唯一命名的新草稿，复制实际用到的媒体，记录计划和源文件 SHA-256；不覆盖、删除或修改原片、已有剪映草稿。失败保留临时输出位置并报告，不把不完整输出宣布为完成。
5. 回读草稿 JSON，核对轨道、片段、源入出点、时序和时长。回读是结构验证，不代表剪映已经成功打开；必要时由用户在对应版本剪映内打开、刷新列表并检查丢素材、字体、音量和同步。

## Python 修改与黑白处理

直接使用 Python 生成新版本草稿，不要求 Computer Use。用户自行验收时，不自动打开、播放或控制剪映。已有计划可修改后重新编译；不原地覆盖现有草稿，不尝试解密新版草稿。

视频/图片片段可设置 `monochrome: true`，调用 `segment.add_filter(draft.FilterType.默片, intensity=100)` 写入可编辑的原生默片滤镜。默认或 `false` 保留原色；按片段设置，不按素材全局设置，因此同一素材可在梦境黑白、梦醒彩色。此例仅说明能力，不作为其他项目的默认创意。

不要用饱和度关键帧 `saturation=-1` 代替黑白滤镜：此前该写法未使目标剪映版本呈现黑白。必须回读滤镜素材及片段 `extra_material_refs` 和强度。文件写入成功不代表资源已加载、草稿首页已识别或画面已经验收；滤镜仍需用户在本机剪映确认，不自动下载或烘焙。

## 支持边界

- 脚本支持一个视频/图片主轨、非重叠裁切、保留或静音原声、多个独立音频轨、音频音量/淡化和基础可编辑文字字幕。时间为整数微秒，不接受隐含变速。
- 除上述原生默片滤镜外，不接受转场、调色、遮罩、取景、文字卡纹理和复杂字幕样式字段；未知字段直接拒绝。不能把完整工程删掉这些字段后称为无损转换。用户同意简化后，另存简化计划并记录差异；烘焙效果或视频提取音频需要另外的实际处理与授权。
- 视频中的音频若要变成独立轨，先在明确授权下提取为音频文件；脚本不把原视频当作独立音频类型偷偷处理。
- 不读取新版非明文模板，不接解码器，不回写剪映里的修改。没有官方渲染 API；不调用 `JianyingController` 自动抢焦点导出，不在剪映 7+ 承诺自动导出。
- 不上传媒体，不发起 RunningHub 任务，不读取账号密钥，不默认联网下载字体、特效或模型。第三方库的本地依赖就绪不代表剪映字体和版本兼容已验证。

完成时区分：通过 MCP 查到什么、实际看/听了什么、只制定了什么计划、生成了哪个草稿、做过哪些结构验证、哪些仍需剪映内检查。若缺少文件或运行环境，交付计划并明确阻塞，不伪造草稿成功。
